# “大全助你选金枕榴莲”首版设计规范

- 日期：2026-08-29
- 状态：用户已批准书面规范
- 产品阶段：门店演示版
- 目标平台：微信内可直接打开的移动端 H5
- 支持品种：泰国金枕榴莲
- AI 模型：OpenAI `gpt-5.6-terra`

## 1. 产品目标

为合作榴莲门店提供一个微信内可直接使用的 AI 外观初筛工具。用户随手拍摄最多 20 颗泰国金枕榴莲，系统识别画面中可辨认的榴莲、自动编号、推荐 3～5 颗候选；用户再补拍候选的果柄、侧面和底部，系统最终推荐 1～3 颗并解释依据与风险。

首版的价值是“快速编号、外观初筛、辅助复核和演示获客”，不是内部品质检测设备，不承诺甜度、果肉比例、生包、死包或内部变质判断。

## 2. 用户与使用场景

- 首批用户：合作榴莲门店的老板、店员及现场顾客。
- 主要设备：iPhone 和安卓手机。
- 使用入口：微信聊天、朋友圈或二维码中的普通 HTTPS 网页链接。
- 拍摄方式：随手拍，不要求平铺；一张合照最多出现 20 颗榴莲。
- 识别原则：只编号系统识别到的榴莲；未识别、严重遮挡或证据不足的榴莲不参与推荐。

## 4. 首版范围

### 4.1 包含功能

1. 微信 H5 打开与手机拍照/相册上传。
2. 合照中的金枕榴莲检测、坐标返回和自动编号。
3. 识别结果覆盖在原图上。
4. 推荐 3～5 颗初筛候选。
5. 候选果柄、侧面、底部三类补拍引导。
6. 最终推荐 1～3 颗并说明依据、风险和证据充分度。
7. 保存带编号结果图。
8. 调用系统分享能力；不支持时提供保存图片的降级方式。
9. 每台浏览器设备 5 个免费体验任务。
10. 额度耗尽弹窗、复制微信号和微信二维码展示。

### 4.2 不包含功能

1. 注册、登录、微信 OAuth 或手机号验证。
2. 订单、支付、会员、套餐和后台运营系统。
3. 用户云端历史记录和原始照片长期存储。
4. 敲击录音、气味传感器、称重和内部成像。
5. 除泰国金枕外的其他榴莲品种。
6. 自训练专用榴莲检测模型。
7. 微信小程序及其审核发布。
8. 正式商用准确率承诺。

## 5. 用户流程

### 5.1 首页

首页展示产品名称、副标题、剩余体验次数、简短能力声明和主按钮“拍照开始选榴莲”。首次使用时说明随手拍最多 20 颗，遮挡严重或未识别的榴莲不会被编号。

### 5.2 合照上传与预处理

用户拍照或从相册选择照片。浏览器执行以下处理：

1. 修正 EXIF 方向。
2. 删除定位和设备元数据。
3. 将最长边限制在 2560 像素以内。
4. 使用约 85% JPEG 质量压缩。
5. 将单张处理后图片限制在 6 MB 以内。

源文件超过 25 MB 时，页面不上传并提示用户改用相机重新拍摄。

### 5.3 第一轮外观初筛

网页将一张合照发送给 `POST /api/analyze-overview`。服务端调用 `gpt-5.6-terra`，返回最多 20 个榴莲目标框、可见证据、风险和初筛状态。

编号由应用根据目标框位置确定，而不是直接采用模型生成的编号：先按纵向位置分行，再按每行从左到右排序，生成连续编号。这样可避免模型返回重复或跳号。

页面展示：

- 本次识别数量；
- 未参与识别的说明；
- 原图上的编号框；
- 3～5 颗优先候选；
- 每颗候选的外观优点、风险和证据充分度。

用户最多选择 3 颗候选进入第二轮。

### 5.4 第二轮候选补拍

每颗候选依次补拍：

1. 果柄；
2. 侧面和果刺；
3. 底部果瓣线。

页面显示拍摄示意、已完成状态和候选编号，防止照片与编号混淆。三张照片齐全后才能提交该候选；一次任务最多分析 3 颗候选、9 张补拍照片。

### 5.5 最终推荐

网页将候选编号、第一轮摘要和补拍照片发送给 `POST /api/analyze-candidates`。服务端返回：

1. 第一推荐；
2. 最多两个备选；
3. 每颗的外观推荐指数；
4. 推荐依据；
5. 风险提示；
6. 证据充分度；
7. 固定能力声明。

“外观推荐指数”是同批候选的相对排序指标，不得描述为甜度概率、成熟准确率或内部品质概率。

### 5.6 保存与分享

页面生成包含产品名称、原图编号、推荐编号、简要理由和固定声明的结果图。优先调用移动端系统分享能力；微信环境不支持直接分享文件时，显示“长按保存结果图”。

## 6. 判断规则

### 6.1 第一轮可用外观证据

- 果形是否端正、饱满；
- 果瓣轮廓与整体对称性；
- 果柄是否可见及其新鲜程度；
- 外壳颜色和果刺形态；
- 可见的开裂、霉斑、黑斑和碰伤；
- 榴莲被遮挡程度和图片清晰程度。

### 6.2 第一轮状态

- `preferred`：优先候选，建议补拍；
- `normal`：未见明显问题，但证据不足；
- `risky`：发现明显可见风险；
- `insufficient`：遮挡、模糊或有效特征太少。

### 6.3 第二轮补充证据

- 果柄切口、颜色、干湿和完整程度；
- 果刺粗细、间距、尖端状态和表面异常；
- 底部果瓣线、裂口和异常斑点；
- 不同角度证据是否相互一致。

模型不得补充照片中不可见的气味、重量、敲击声、果肉颜色、糖度和内部状态。

## 7. 技术架构

```text
微信 H5（React + TypeScript + Vite）
  ├─ 手机相机/相册
  ├─ 图片方向校正、压缩和元数据清除
  ├─ 编号覆盖层与候选选择
  ├─ 结果图生成、保存和分享
  └─ 设备标识与剩余额度显示
          ↓ same-origin HTTPS
Cloudflare Worker
  ├─ 静态网页资源
  ├─ 请求校验和额度控制
  ├─ OpenAI API 密钥 Secret
  ├─ OpenAI Responses API 客户端
  ├─ 结构化结果验证和坐标清理
  └─ Cloudflare KV 最小额度记录
          ↓
OpenAI Responses API / gpt-5.6-terra
```

### 7.1 前端边界

前端只负责拍摄、预处理、交互、编号绘制和结果呈现，不持有 OpenAI API 密钥，不直接调用 OpenAI。

### 7.2 Worker 边界

Worker 负责同源 API、输入校验、额度、AI 调用、结构化输出验证和错误映射。AI 客户端、额度模块和结果清理模块必须保持独立，以便后续将检测部分替换成专用模型。

### 7.3 最小持久化

首版不建立用户或照片数据库。Cloudflare KV 仅保存：

- 随机设备标识的不可逆摘要；
- 网络 IP 的加盐摘要；
- 已成功创建的任务次数；
- 必要的计数更新时间。

KV 不保存姓名、微信号、原始 IP、原始照片或 AI 结果正文。

## 8. OpenAI 数据契约

所有 AI 响应使用 JSON Schema 约束并在服务端再次验证。模型输出不得直接作为 HTML 注入页面。

### 8.1 第一轮结果

```json
{
  "image_quality": "good | usable | poor",
  "warnings": ["string"],
  "fruits": [
    {
      "box_2d": [0, 0, 1000, 1000],
      "visibility": "high | medium | low",
      "status": "preferred | normal | risky | insufficient",
      "evidence": ["string"],
      "risks": ["string"],
      "evidence_strength": "high | medium | low"
    }
  ]
}
```

`box_2d` 使用归一化坐标。服务端拒绝非四元数组、越界框、面积过小框和明显重复框，并最多保留 20 个框。

### 8.2 第二轮结果

```json
{
  "ranking": [
    {
      "candidate_id": 1,
      "rank": 1,
      "appearance_score": 82,
      "evidence": ["string"],
      "risks": ["string"],
      "evidence_strength": "high | medium | low"
    }
  ],
  "summary": "string",
  "limitations": ["string"]
}
```

服务端确保候选编号属于当前任务、排名连续、指数处于 0～100，且最多返回 3 颗。

## 9. 额度与防刷

### 9.1 体验额度

- 每台浏览器设备总共 5 个免费体验任务。
- 第一次成功生成合照初筛结果时创建任务并扣除 1 次。
- 同一任务的候选补拍、重看结果和生成结果图不重复扣除。
- 无榴莲、严重模糊、超过 20 颗、输入校验失败、OpenAI 超时或 OpenAI 失败时不扣除。
- 用户中途退出已成功创建的任务，不退还额度。

### 9.2 演示级身份边界

首版通过浏览器随机设备标识近似识别用户。清理浏览器数据、更换浏览器或更换设备可能重新获得额度。这是用户已知并接受的演示版边界。正式商用版若需严格识别人，应改用微信授权或手机号登录。

### 9.3 网络防刷

同一网络 IP 每 24 小时最多成功创建 50 个任务。该限制只用于防止公开链接被批量刷取，不替代设备 5 次额度。

### 9.4 额度耗尽转化

第 5 次任务创建后，首页剩余额度显示为 0。再次开始新任务时弹出：

> 免费体验额度已用完。想获得更多额度，可添加微信 daquan088。

弹窗提供：

1. “复制微信号 daquan088”按钮；
2. 完整微信二维码图片；
3. “长按识别二维码添加好友”提示。

用户提供的源图片位于 `D:\海报照片\微信图片_20260829221306_248_23.jpg`。实施时将原图复制为新项目独立素材 `public/assets/daquan-wechat-qr.jpg`，不修改源文件。

## 10. 界面设计方向

- 移动端竖屏优先；
- 榴莲绿、果肉金黄和米白为主色；
- 真实、专业、接地气，不做复杂科技大屏；
- 主要按钮适合单手操作，字号和点击区域适合微信；
- 不使用虚假的分析百分比进度；
- 编号框在不同背景上保持清晰；
- 优先候选使用金黄色，风险目标使用橙红色；
- 二维码必须使用真实 `<img>` 元素完整展示，不放在 Canvas 或 CSS 背景中，以保留长按识别能力。

主要界面状态：

1. 首页；
2. 合照选择与预览；
3. 分析等待；
4. 初筛编号结果；
5. 候选补拍向导；
6. 最终推荐；
7. 结果图分享；
8. 额度耗尽弹窗；
9. 各类错误和重试状态。

## 11. 异常处理

- 无榴莲：提示换角度重新拍，不扣次数；
- 超过 20 颗：停止分析，提示减少画面中的榴莲，不扣次数；
- 图片过暗或模糊：提示重拍，不扣次数；
- 部分遮挡：只编号通过验证的目标，并说明未识别目标不参与推荐；
- 重复框或越界框：服务端清理后再编号；
- 结构化输出不合法：服务端允许一次受控重试，仍失败则返回友好错误；
- OpenAI 超时、无权限、余额不足或限流：不扣次数，返回可重试或联系管理员提示；
- 第二轮候选编号不一致：拒绝请求并要求重新选择；
- 保存或分享失败：保留页面结果并提示长按截图或重试。

## 12. 安全与隐私

1. `OPENAI_API_KEY` 只存于新 Cloudflare Worker 的加密 Secret。
2. API 密钥、Cloudflare 凭据和本地配置文件不得提交 GitHub。
3. 所有 API 仅允许同源访问，并校验 Content-Type、图片数量和大小。
4. 前端上传前删除可删除的图片元数据。
5. 页面明确说明照片会发送给 OpenAI 完成分析。
6. 应用不主动长期保存原始照片和分析结果。
7. 日志不得记录图片 Base64、API 密钥、完整 IP 或微信二维码解析内容。
8. AI 返回文本必须转义后展示，禁止直接执行模型输出。

## 13. 测试策略

### 13.1 自动测试

- 坐标归一化、越界修正、重复框清理；
- 编号排序的稳定性；
- JSON Schema 验证和错误映射；
- 设备 5 次额度、同任务不重复扣费；
- 无效输入和 AI 失败不扣次数；
- IP 24 小时防刷上限；
- 图片压缩、方向校正和元数据处理；
- 结果图生成与文案完整性。

### 13.2 浏览器测试

- iPhone 微信浏览器；
- 安卓微信浏览器；
- 手机 Safari 和 Chrome 作为辅助；
- 相机、相册、返回页面、页面刷新和弱网场景；
- 微信号复制；
- 二维码完整显示和长按识别；
- 保存结果图和分享降级流程。

### 13.3 真实门店测试

使用合作门店提供的泰国金枕真实照片覆盖：

- 5～10 颗较清晰合照；
- 15～20 颗普通遮挡合照；
- 暗光、反光、背景复杂和局部模糊；
- 正常果、开裂果、明显受损果；
- 候选果柄、侧面和底部补拍。

真实照片只用于本地或授权测试，不提交公开 GitHub。首版验收关注流程可用性、编号合理性和解释边界，不用少量样本宣称正式准确率。

## 14. 验收标准

1. 微信内可直接打开 HTTPS H5 并调用相机或相册。
2. 随手拍最多 20 颗金枕时，识别到的榴莲能获得连续编号。
3. 漏检目标不编号、不参与推荐，页面有明确说明。
4. 第一轮能返回 3～5 颗候选及可见依据；不足 3 颗有效目标时按实际数量返回。
5. 用户最多选择 3 颗并完成三类补拍。
6. 最终能返回 1～3 颗排序、依据、风险和固定能力声明。
7. 结果图可保存；分享不可用时有明确降级路径。
8. 每台设备第 6 次创建任务时被拦截，并正确显示微信号和二维码。
9. 复制微信号和二维码长按识别在微信环境可用。
10. API 失败和无效照片不扣体验次数。
11. OpenAI API 密钥不出现在前端包、GitHub 和日志中。
12. 旧本地项目、旧 GitHub 仓库、旧 Cloudflare 项目和旧线上地址保持不变。
