# 0002 - 腾讯 CloudBase 微信移动端演示部署

**Status:** proposed
**Date:** 2026-08-31
**Spec:** “大全助你选金枕榴莲”首版已批准规范及后续微信可访问部署要求
**Deciders:** 待大全确认

## Context

原 Cloudflare `workers.dev` 地址在电脑端可用，但华为手机的微信内置浏览器无法稳定打开，而且账号子域名包含客户名称缩写，不能作为对外链接。用户要求保留旧项目，并另行生成一个能在微信手机端打开的新链接。

腾讯 CloudBase 新环境 `daquan-durian-picker-d5aa5eeef39` 可提供国内 HTTPS 系统域名、云函数和 PostgreSQL。实测事件函数网关可以完成 GPT-5.6 Terra 初筛，但补拍请求体的可用上限明显低于原 Cloudflare Worker。三颗候选共九张补拍图无法可靠通过该网关。

## Decision

- 新增独立 CloudBase 部署，不修改或覆盖旧 Cloudflare Worker、旧仓库和旧链接。
- React H5、API 适配器和模型调用部署在同一个 CloudBase 事件函数中；API Key 仅保存在函数环境变量。
- 设备 5 次额度、IP 日限额、任务状态和幂等租约迁移到新环境 PostgreSQL，并通过 `durian_quota` 存储函数原子提交。
- 为适应事件网关，演示版初筛图压缩到 70 KiB 以内；补拍阶段每个完整任务精拍一颗候选的果柄、果身和果底，每张控制在 18 KiB 以内。
- 同一任务补拍仍不重复扣额度，模型仍固定 `gpt-5.6-terra`，可见外观证据边界不变。

## Consequences

- 华为及其他安卓手机可使用不含客户姓名的腾讯云 HTTPS 链接进入演示。
- 第一轮仍可识别和编号最多 20 颗榴莲，但第二轮由“最多三颗相对比较”暂时缩减为“一颗精拍复核”。这是演示部署限制，不应描述为完整商用能力。
- 较强压缩会降低远距离小目标和细节判断质量；真实门店测试必须重点验证 15～20 颗合照。
- 后续接入正式自有域名、对象存储直传或 HTTP 云托管后，应恢复最多三颗、九张补拍图，并将本 ADR supersede。

## Alternatives Considered

- **继续使用原 `workers.dev`：** 微信手机端不可用，且链接含客户名称缩写。
- **使用未完成的自有官网域名：** 用户明确暂不使用。
- **EdgeOne 临时预览链接：** 中国区预览链接有效期短，不适合交付。
- **CloudBase 云托管：** 当前账号未开通对应资源，创建服务失败，未产生服务。
- **把 API Key 放到前端：** 会泄露密钥，违反安全规范。
